# Customer JSON API v1

`/api/v1` — версионированный JSON API для web-клиента и
`apps/customer-mobile`. Он работает внутри `apps/web`, использует общую
PostgreSQL базу и не является отдельным сервисом.

Локальный base URL: `http://localhost:3000/api/v1`.

## Совместимость

- Существующие поля и значения в `/api/v1` не меняются несовместимо.
- Новые необязательные поля и новые error reasons могут добавляться без новой
  версии.
- Несовместимые изменения публикуются под новым префиксом API.
- Все ответы имеют `Content-Type: application/json` и `Cache-Control: no-store`.

Успешный ответ:

```json
{
  "ok": true,
  "data": {}
}
```

Ошибка:

```json
{
  "ok": false,
  "error": {
    "code": "validation_failed",
    "message": "The cart cannot be quoted.",
    "reason": "minimum_order",
    "fieldErrors": {
      "items.0.quantity": "integer_1_99_required"
    }
  }
}
```

`error.code` задаёт общий класс ошибки. Необязательный `error.reason` —
стабильная машинная причина доменной ошибки; `message` предназначено для
диагностики, а не для ветвления клиентской логики. `fieldErrors` присутствует
только для ошибок отдельных полей.

## Авторизация

Мобильное приложение передаёт токен из ответа OTP verify:

```http
Authorization: Bearer <accessToken>
```

Web может использовать тот же bearer token либо session cookie. Токен нельзя
логировать или сохранять в открытом виде. `DELETE /auth/session` отзывает
переданный токен и удаляет cookie.

В текущем cash-only MVP OTP работает только через dev/closed-pilot provider.
SMS не отправляется. `devCode` возвращается только в разрешённом development
окружении; в остальных окружениях клиент получает код внешним согласованным
пилотным способом.

## Endpoints

| Метод | Путь | Auth | Назначение |
| --- | --- | --- | --- |
| `POST` | `/auth/otp/request` | public | Запросить код для телефона |
| `POST` | `/auth/otp/verify` | public | Проверить код и получить session token |
| `GET` | `/auth/session` | customer | Получить текущего пользователя |
| `DELETE` | `/auth/session` | token/cookie | Завершить сессию |
| `GET` | `/restaurants` | public | Список активных ресторанов |
| `GET` | `/restaurants/{id-or-slug}/menu` | public | Активное меню ресторана |
| `POST` | `/cart/quote` | customer | Проверить корзину и рассчитать итог |
| `POST` | `/orders/cash` | customer | Создать cash-заказ |
| `GET` | `/orders/{number}` | customer | Статус своего заказа и история |

Защищённые order endpoints всегда ограничены текущим customer ID: пользователь
не может получить заказ другого клиента по известному номеру.

## Основной сценарий

### 1. OTP

```json
POST /auth/otp/request
{ "phone": "+77000000002" }
```

```json
POST /auth/otp/verify
{ "phone": "+77000000002", "code": "000000" }
```

Verify возвращает `accessToken`, `expiresAt` и `user`.

### 2. Ресторан и меню

Вызвать `GET /restaurants`, затем
`GET /restaurants/tengri-kitchen/menu`. Для checkout необходимо сохранить
`restaurant.id` и `menuItem.id`, а не только slug или отображаемое имя.

### 3. Расчёт корзины

```json
POST /cart/quote
{
  "restaurantId": "<restaurant UUID>",
  "items": [
    { "menuItemId": "<menu item UUID>", "quantity": 1 }
  ],
  "deliveryAddress": {
    "label": "Дом",
    "addressLine": "проспект Абая, 10",
    "latitude": 43.238949,
    "longitude": 76.889709
  }
}
```

Ответ содержит `itemsSubtotal`, `deliveryFee`, `serviceFee`, `total` и
`currency`. Все денежные значения — целые minor units: `100` равно `1 KZT`.
Клиент не должен самостоятельно пересчитывать серверный итог.
Координаты передаются в WGS84: latitude от `-90` до `90`, longitude от `-180`
до `180`.

### 4. Cash-заказ

```json
POST /orders/cash
{
  "restaurantId": "<restaurant UUID>",
  "items": [
    { "menuItemId": "<menu item UUID>", "quantity": 1 }
  ],
  "deliveryAddress": {
    "addressLine": "проспект Абая, 10",
    "latitude": 43.238949,
    "longitude": 76.889709
  },
  "idempotencyKey": "<new UUID generated by the client>",
  "customerComment": "Позвонить у двери"
}
```

Оплата всегда `cash_to_courier`; API не принимает способ оплаты и не создаёт
онлайн-платёж. Клиент генерирует один `idempotencyKey` на попытку checkout и
повторяет тот же ключ при сетевом retry. Повтор с тем же payload возвращает тот
же заказ; повтор с изменённым payload возвращает HTTP `409` и reason
`checkout_request_conflict`.

### 5. Статус

`GET /orders/{number}` возвращает текущее `status`, локализованный
`statusLabel`, итог и хронологический массив `events`. Для MVP мобильный клиент
может обновлять endpoint polling-ом; push-уведомления не требуются.

## Локальная проверка

После `npm run dev:local`, миграций и seed:

```powershell
npm.cmd run auth:reset-local-rate-limits
npm.cmd run smoke:customer-api
```

Smoke проверяет полный API-путь
OTP → restaurant → menu → quote → cash order → status → logout и создаёт
реальный заказ. Он принимает только localhost URL и дополнительно требует,
чтобы `/api/health` сообщил `RELEASE_TARGET=local`.
